# qlx86 – x86-32 OS-9000 Linker

**Status:** Phase 12d complete – Full linker pipeline working ✓

## Overview

`qlx86` links ROF (Relocatable Object Format) modules produced by `qox86` (the x86-32 assembler) into executable OS-9000 modules for x86 architecture.

```
qcc_backend.ir → qirx86 → .a (assembly) → qox86 → .r (ROF) → qlx86 → .mod (OS-9000 Module)
```

## Architecture

### Phase 12a: ROF Input Parser
- Reads `.r` files generated by qox86
- Parses 56-byte big-endian header (DEADFACE sync word)
- Extracts global symbols, code/data sections
- Validates header integrity

### Phase 12b: Memory Layout
- Calculates final memory layout
- Maps code and data sections to output offsets
- Supports multiple ROF objects (for future library linking)

### Phase 12c: OS-9000 Module Header Generator
- Writes 56-byte OS-9000 module header (big-endian format)
- Sync word: 0xDEADFACE
- Attributes field: 0x8000 (executable, in-memory)
- Code/Data/BSS size fields from ROF

### Phase 12d: Relocation Processing
- Resolves external symbol references
- Applies address relocations to code
- Handles cases where symbols are undefined (defaults to 0x00000000)

## Usage

```bash
qlx86 <input.r> -O=<output.mod>
```

### Example

```bash
# From qox86 assembler output
qox86 final.a -O=final.r

# Link to executable module
qlx86 final.r -O=final.mod

# Result: 685 bytes OS-9000 x86 module
#   - 56 byte header (DEADFACE, attributes, sizes)
#   - 629 bytes code
#   - 0 bytes initialized data
```

## Output Format

The generated `.mod` file follows OS-9000/x86 binary module format:

```
Offset  Size  Field
------  ----  -----
0x00    4     Sync word (0xDEADFACE)
0x04    2     Type/Language
0x06    2     Attributes (0x8000 = executable)
0x08    2     Error code
0x0A    2     Reserved
0x0C    2     Reserved
0x0E    2     Edition
0x10    4     Static/BSS size
0x14    4     Initialized data size
0x18    4     Code size
0x1C    4     Stack size
0x20    4     Entry point
0x24    4     Trap entry
0x28    4     Remote data
0x2C    4     Remote initialized data
0x30    4     Debug info
0x34    0     Code section begins (little-endian x86-32)
```

## Known Limitations

1. **Single ROF input only** – Library linking (multiple `.r` files) not yet implemented
2. **No external symbol resolution** – All external symbols default to 0x00000000
3. **No relocation records** – Limited to internal symbol references only
4. **No stack estimation** – Stack size hardcoded to 4 KB
